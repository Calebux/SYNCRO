# Tor hidden-service deployment (.onion)

This document describes how to run the SYNCRO dashboard as a Tor hidden service using a Docker compose setup.

## What you get
- A generated **.onion** address for the dashboard
- End-to-end encryption via Tor (no public HTTPS termination required)
- One-command deployment using Docker Compose

## Limitations / Notes
- **No HTTPS needed**: Tor serves the hidden service over HTTP semantics.
- Some Tor Browser / setup combinations may behave differently with browser extensions.
- The SYNCRO frontend already avoids relying on `upgrade-insecure-requests` to support `.onion` HTTP semantics.
- If you use features that depend on external browser extensions (e.g., crypto wallet extensions), Tor Browser compatibility varies by environment.

## Files
- `deploy/tor/docker-compose.tor.yml`
- `deploy/tor/torrc`

## Prerequisites
- Docker Desktop (or Docker Engine) and Docker Compose.
- The SYNCRO app image for the dashboard must be buildable using `Dockerfile.syncro-dashboard` (see `client/`/root Dockerfiles as applicable in your environment).

## One-command deployment
From repository root:

```bash
docker compose -f deploy/tor/docker-compose.tor.yml up -d --build
```

## Discover the generated .onion address
The onion address is generated by Tor and persisted in the Tor data volume (`tor_data`).

1. View Tor logs:

```bash
docker compose -f deploy/tor/docker-compose.tor.yml logs -f tor
```

2. Look for a line that includes the hidden service hostname, typically derived from `HiddenServiceDir`.

### If you need to extract it directly from the container
```bash
docker compose -f deploy/tor/docker-compose.tor.yml exec tor sh -c "cat /var/lib/tor/hidden_service/hostname 2>/dev/null || cat /var/lib/tor/hidden_service/hostname"
```

The output should be a value like:
`xxxxxxxxxxxxxxxx.onion`

## Verify access
Open the onion address in Tor Browser:
- `http://<your-onion-address>/`

No HTTPS configuration should be required.
